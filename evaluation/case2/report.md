# Отчёт: Case 2 — оценка плана на checkpoint-ветке

Дата проверки: 19 августа 2026.  
Ветка с результатами: `feat/checkpoints`.  
Режим оценки: `plan_checkpoint_only`.

## Цель

Проверить, как уточнённая постановка исследования о генерации молекул по
траекториям эволюционной оптимизации меняет план, создаваемый системой, по
сравнению с исходным вопросом. Отдельно проверить, доступны ли MCP-инструменты
для ответов на вопросы по новой базе научных работ.

## Состав прогона

Проверены две версии одного кейса:

| Вариант | Входной файл | Run ID | Статус |
|---|---|---|---|
| Только исходный вопрос | `question_only.txt` | `case2_question_only_checkpoint_20260812T155017Z_619b2707` | `awaiting_review` |
| Вопрос с постановкой и H1–H5 | `question_with_refinements.txt` | `case2_with_refinements_checkpoint_20260812T195528Z_16c16683` | `awaiting_review` |

Оба запуска сохранены в `evaluation.sqlite3`, а их финальные состояния — в
двух ZIP-бандлах checkpoint `T0_before_hitl`. Целостность базы проверена
`PRAGMA integrity_check` (`ok`), каждого бандла — `unzip -t`.

Запуски намеренно остановлены на fail-closed границе review: план был создан и
сохранён, но не одобрен. Поэтому не запускались GOLEM, обучение моделей,
генерация SMILES, docking, CoderAgent и любые экспериментальные задачи. Это
проверка качества планирования, а не проверка научных гипотез H1–H5.

## Результат сравнения планов

| Показатель | Только вопрос | С уточнениями |
|---|---:|---:|
| Число гипотез в плане | 3 | 5 |
| Число задач | 1 | 5 |
| Оценка длительности | 240 минут | 600 минут |
| Маршрутизация | 1 × `coder` | 5 × `coder` |
| Доступный инвентарь инструментов | пустой/недоступен | пустой/недоступен |

Исходный вопрос был свёрнут в одну end-to-end задачу с отдельными endpoint
гипотезами для Docking score, SA и валидности. В нём отсутствовали GOLEM,
GSK-3β, MCPhub, CVAE, объём 10 000 траекторий, novelty и абляции длины
траектории и KL-регуляризации.

Уточнённая постановка привела к пятиэтапному плану: подготовка не менее 10 000
GOLEM-траекторий и статического контроля; обучение trajectory/static CVAE;
оценка совместной метрики и novelty; абляция информативности/длины траектории;
абляция KL-регуляризации. Следовательно, уточнения существенно изменили и
содержание, и структуру плана.

Ограничение результата: формулировки гипотез, сгенерированные планировщиком,
частично разошлись с переданными H1–H5 (например, метка H5 в тексте плана), хотя
пятая задача по существу посвящена KL-абляции. Это следует исправлять перед
исполнением плана.

Полное сопоставление и замечания находятся в `comparison.md`.

## Что происходило в более ранних попытках

Важно отличать финальные checkpoint-прогоны от более ранней попытки
`case2_question_only_20260812T141529Z_8179995e` (`question_only_validkey.log`):

- первые попытки остановились ещё на запросе к LLM с `401 User not found`;
- в попытке с рабочей авторизацией MCP/RAG-поиск всё равно вернул ошибку
  `Embedder not initialized`, а публичный поиск MCP-серверов — ноль результатов;
- fallback `coder` сгенерировал синтетический набор из 500 траекторий по 20
  молекул (10 000 молекулярных записей) и выполнил проверки формата,
  валидности SMILES и монотонности surrogate fitness;
- обучение модели было начато, но тест с физическим batch size 64 завершился
  `exit code 137` (OOM). Попытка была прервана и не дала законченного сравнения
  trajectory/static моделей или целевых Docking/SA/Validity метрик.

Таким образом, в прошлом прогоне частично отработал только fallback-кодер с
синтетической surrogate-задачей. MCP для новой базы не отработал ни тогда, ни в
финальных checkpoint-прогонах.

## Проверка MCP для новой базы

Для вопросов к базе научных работ предусмотрен MCP `paper-analysis` с
инструментом `explore_chemistry_database(task)`. Его ожидаемый путь подключения
задаётся переменной `MCP__PAPER_ANALYSIS_URL`; дополнительный MCP поиска статей
использует `MCP__PAPERS_SEARCH_URL`.

Фактическая проверка текущего окружения 19 августа 2026:

| Проверка | Результат |
|---|---|
| `MCP__PAPER_ANALYSIS_URL` в `.env` | не задана |
| `MCP__PAPERS_SEARCH_URL` в `.env` | не задана |
| Создание toolset `paper_analysis` | пропущено как optional-конфигурация |
| Локальные TCP-порты `5433`, `7331`, `7332`, `7333` | connection refused |
| Docker daemon | не запущен/недоступен |
| Вызов вопроса к новой базе | не выполнен: MCP endpoint отсутствует |

Итог: на момент проверки MCP **не отработал**, поскольку не был подключён и
сервис базы не был доступен. Это инфраструктурный блокер, а не отрицательный
ответ базы и не результат содержательной проверки качества RAG. В checkpoint
прогонах также не было доступных инструментов, поэтому все запланированные
задачи получили fallback-маршрут `coder`.

## Как завершить end-to-end проверку MCP

1. Запустить или предоставить URL сервиса `paper-analysis` с доступом к новой
   Chroma-базе и embedding/reranker-сервисам.
2. Добавить в локальный `.env` (не коммитить):

   ```dotenv
   MCP__PAPER_ANALYSIS_URL=http://<host>:7331/mcp
   # при необходимости
   MCP__PAPERS_SEARCH_URL=http://<host>:<port>/mcp
   ```

3. Выполнить минимум один предметный вопрос, например: «Какие работы в базе
   описывают генерацию SMILES с conditional VAE или transformer для molecular
   optimization?». Успешный ответ должен содержать непустые `answer` и
   `metadata` с `text_context` и `image_context`, а не fallback
   `Could not extract any data from DB.`
4. Повторить вопрос, использованный в Case 2, и зафиксировать raw MCP-ответ,
   время, число retrieved chunks и ошибки сервиса. После этого можно запускать
   полный экспериментальный pipeline только после отдельного одобрения review.
